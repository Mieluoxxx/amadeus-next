# E-mote 角色表情与驱动规范文档

本文档定义 Amadeus 当前桌面角色（牧濑红莉栖 `kurisu_ab_white` 白衣 B 姿态）在 **E-mote / FreeMote** 渲染引擎下支持的全部表情体系、底层时间线映射、别名归一化规则及动画动力学特性。

---

## 1. 核心表情清单 (Core Expressions · 8 种)

系统在内部将所有输入抽象为 8 种标准枚举类型（`Emotion`），分别对应 E-mote PSB 模型主时间线的专用动作片段：

| 内部枚举 (`Emotion`) | 推荐提示词 Preset | 底层时间线标签 | 视觉表现特征 | 角色语境与适用情境 |
| :--- | :--- | :--- | :--- | :--- |
| `neutral` | `normal` | `表情_普通` | 目光平视、嘴角自然放松、无特殊起伏 | 默认常态、客观陈述、科学原理解释 |
| `smile` | `smile` | `表情_笑う` | 眉眼微弯、嘴角上扬带笑意 | 友好问候、调侃打趣、解出难题时的欣慰 |
| `thinking` | `thinking` | `表情_困る00` | 眉头轻蹙、带有困惑与纠结感 | 遇到难以立刻解答的问题、迟疑、思考转折 |
| `serious` | `serious_speaking` | `表情_睨む` | 双眉微压、眼神专注锐利（微瞪视） | 严肃警告、强调关键结论、反驳谬论 |
| `sad` | `sad` | `表情_哀しい00` | 眉角下垂、眼神落寞黯淡 | 坏消息、实验失败、真诚道歉、同情安慰 |
| `shy` | `shy` | `表情_照れる` | 脸颊浮现红晕、眼神偏离游移 | 口是心非反差萌、被直球夸奖、触及个人隐私 |
| `surprise` | `surprised` | `表情_驚き00` | 瞳孔放大、眉毛挑高、微张嘴 | 听到意外发现、突发状况、得知不可思议的消息 |
| `angry` | `angry` | `表情_怒る` | 倒八字眉、嘴角紧绷下撇、眼神带怒气 | 被激怒、强烈反驳、羞愤抗议（经典傲娇） |

## 2. 别名归一化映射 (Alias Normalization)

代码在 `src/shared/character.ts` 中内置了多语言及常见近义词归一化机制，LLM 输出或外部事件触发以下词汇时，均会被安全映射到对应的核心枚举：

| 目标枚举 (`Emotion`) | 匹配的所有合法别名 (Aliases) |
| :--- | :--- |
| `neutral` | `normal`, `neutral` |
| `smile` | `happy`, `smile`, `微笑`, `开心` |
| `thinking` | `thinking`, `think`, `work`, `working`, `思考` |
| `serious` | `serious`, `serious_speaking`, `speaking_serious`, `严肃` |
| `sad` | `sad`, `disappointed`, `sadness`, `悲伤`, `失望` |
| `shy` | `shy`, `blush`, `害羞` |
| `surprise` | `surprise`, `surprised`, `惊讶` |
| `angry` | `angry`, `mad`, `furious`, `生气` |

> 若输入的表情名称未命中上述任意别名，系统将平滑兜底为 `neutral`（`表情_普通`），杜绝因非法标签导致模型动画中断。

## 3. 动力学扩展与智能行为控制

E-mote 表现不仅限于静态表情切帧，系统在运行时实现了多项专有动力学算法与生命周期保护：

### 3.1 思考状态视线往复扫描 (Thinking Scan)
* **触发机制**：当 Agent 处于工具调用中（`activity: 'tool'`）或后台推理阶段（`activity: 'thinking'`）时，角色自动进入 `表情_困る00`。
* **运动动力学**：
  - 启动独立的眼球与头部扫描循环，解耦眼球往复运动与头部微摆；
  - `head_UD`（头部俯仰）以 2000ms 周期微幅摆动；
  - `face_eye_LR`（眼球左右水平移动）以 3000ms 缓动平滑巡视，模拟视线在思考时四处游移；
  - 具备 600ms 平滑入场过渡与 350ms 退出淡出，避免动作突兀抽搐。
* **超时保护**：若后台长时间无新语音注入，等待 30 秒后自动超时退回 `neutral` 常态，防止角色持续面露难色。

### 3.2 口播中思考表情自动复原 (Spoken Thinking Reset)
* 避免角色在长篇回答中全程保持困惑脸：
* 当语音播放状态（`playing`）下被赋予 `thinking` 表情时，系统启动 **2000ms 计时器**；
* 超过 2 秒未收到新表情指令时，自动将表情平滑归位至 `neutral`（平静），确保自然过渡。

### 3.3 音频能量口型驱动 (Lip Sync)
* **实时能量映射**：`AudioWorklet` 计算 PCM 音频的实时 RMS 振幅（`report.rms * calibration.mouthGain`）；
* **开合度映射**：将连续能量映射至 E-mote 底层 `face_talk` 参数（范围 `0.0 ~ 5.0`）；
* **静音保护**：内置 `silenceThreshold` 静音门限，环境杂音或语间停顿时强制闭嘴（`setMouth(0)`）。

### 3.4 离散部件延迟写入 (Snap Delay)
* 头部与身体旋转具备 350ms 的连续线性过渡插值；
* 为了避免过渡中途图层发生错位或撕裂，离散部件选择器在过渡中点延迟 **175ms** 写入，确保层级渲染完美对齐。

## 4. 提示词编写与调度规范

在当前双语对话格式中，表情标签必须遵守以下契约：

```text
<zh>中文字幕行</zh><jp>[EMO preset=NAME]日语音频口播行</jp>
```

### 编写约束：
1. **位置规范**：`[EMO preset=NAME]` 必须写在 `<jp>` 标签内、对应日语句子的**最前方**。
2. **切换频次**：在较长回复中，建议每 **2 ~ 3 句话**根据语意递进更换一次表情；除非通篇确实处于单一情绪，否则切忌全篇不带表情或全篇保持同一个表情。
3. **分词器脱壳**：
   - 前端流式解析器捕获 `[EMO preset=NAME]` 后，根据字符偏移量生成 `cues` 传递给渲染管线；
   - 渲染管线基于 Fish Audio 返回的毫秒级音频时间戳，在声音念到该句的准确时刻切换角色表情。
